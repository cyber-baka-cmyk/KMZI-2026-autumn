# Лабораторная работа №2. Асимметричное шифрование: ядро RSA, оптимизация CRT и схема OAEP с Constant-time защитой

Язык реализации: C++. Категорически запрещено использование языков со встроенным автоматическим бесконечным расширением памяти под переменные (например, Python, Ruby, JavaScript) из соображений информационной безопасности. Использование сторонних криптографических библиотек, библиотек для работы с большими числами разрешено только для арифметики больших чисел.

**Цель работы:** разработка защищенного ядра асимметричного шифрования на базе алгоритма RSA, оптимизация процесса расшифрования с использованием Китайской теоремы об остатках (CRT) и реализация строгой вероятностной схемы дополнения (Padding) OAEP с защитой от атак по побочным каналам (Constant-time). 

Обязательный теоретический минимум:
* математика генерации ключей RSA: алгоритмы поиска больших простых чисел, тест простоты Миллера-Рабина, вычисление функции Эйлера $\phi(N)$ или функции Кармайкла $\lambda(N)$, поиск экспонент $e$ и $d$;
* алгоритм оптимизации RSA-CRT: предварительное вычисление компонент $d_p, d_q, q_{inv}$ и ускоренное расшифрование/подписание с использованием алгоритма Гарнера;
* схема Optimal Asymmetric Encryption Padding (OAEP): рандомизация открытого текста, реализация Mask Generation Function (MGF1) на базе хеш-функций, маскирование блоков Seed и Data Block;
* атаки Блейхенбахера и побочные каналы: изоляция времени выполнения процедуры проверки паддинга OAEP, устранение зависимости потребления тактов от валидности шифротекста (запрет раннего выхода return при ошибках распаковки).

Проект должен состоять из трех логически изолированных модулей:
1. _Модуль теории чисел и арифметики RSA._ Реализация генерации ключей и базовых математических примитивов (построение на базе разрешенной BigInt-библиотеки). Модуль должен инкапсулировать вычисление НОД (расширенный алгоритм Евклида) и модульное возведение в степень.
2. _Вычислительное ядро RSA с CRT._ Модуль, выполняющий математическое шифрование $c = m^e \pmod N$ и расшифрование $m = c^d \pmod N$. Расшифрование обязано использовать алгоритм CRT для ускорения вычислений.
3. _Схема паддинга OAEP и Constant-Time защиты._ Модуль инкапсуляции пользовательских сообщений перед шифрованием и деинкапсуляции после расшифрования. Внедрение механизмов Constant-Time (согласно графе «Задача оптимизации» в таблице вариантов).

**Теоретическая база**

### 1. Математика криптосистемы RSA

Алгоритм RSA базируется на вычислительной сложности задачи факторизации больших целых чисел.

**_Генерация ключей_**

Генерируются два больших простых числа $p$ и $q$ одинаковой битовой длины. Вычисляется модуль $N = p \cdot q$. Вычисляется значение функции Кармайкла $\lambda(N) = \text{lcm}(p-1, q-1)$ (или функции Эйлера $\phi(N) = (p-1)(q-1)$). Выбирается открытая экспонента $e$ (обычно $e = 65537$), такая что $1 < e < \lambda(N)$ и $\gcd(e, \lambda(N)) = 1$. Вычисляется секретная экспонента $d \equiv e^{-1} \pmod{\lambda(N)}$. Публичный ключ: $(N, e)$. Приватный ключ: $(d, p, q)$.

_**Базовое шифрование и расшифрование**_

Для сообщения $m$, где $0 \le m < N$:

$$c \equiv m^e \pmod N$$
$$m \equiv c^d \pmod N$$

### 2. Ускорение расшифрования через Китайскую теорему об остатках (CRT)

Возведение в степень $d$ по модулю $N$ требует значительных вычислительных ресурсов. Поскольку $p$ и $q$ известны владельцу секретного ключа, вычисления можно разбить на два независимых процесса по модулям $p$ и $q$, что ускоряет операцию почти в 4 раза. Предварительные вычисления (на этапе генерации ключа):

$$d_p = d \pmod{p-1}$$
$$d_q = d \pmod{q-1}$$
$$q_{inv} = q^{-1} \pmod p$$

**_Алгоритм Гарнера для расшифрования $m = c^d \pmod N$:_**

1. $m_1 = c^{d_p} \pmod p$
2. $m_2 = c^{d_q} \pmod q$
3. $h = q_{inv} \cdot (m_1 - m_2) \pmod p.$
4. Если $(m_1 - m_2) < 0$, необходимо добавить $p$.$m = m_2 + h \cdot q$

### 3. Схема дополнения OAEP (Optimal Asymmetric Encryption Padding)

Сырой RSA детерминирован и уязвим к атакам на основе выбранного шифротекста (CCA). Схема OAEP (PKCS#1 v2.1) делает алгоритм вероятностным. Пусть $k$ — длина модуля $N$ в байтах, $hLen$ — длина хеша в байтах (например, 32 для SHA-256). Длина сообщения $M$ не может превышать $k - 2 \cdot hLen - 2$ байт.
_**Процедура упаковки (Padding):**_
1. Формируется метка (Label), по умолчанию пустая строка. Вычисляется $lHash = \text{Hash}(\text{Label})$.
2. Формируется строка паддинга $PS$ из нулевых байтов (0x00) длины $k - \text{len}(M) - 2 \cdot hLen - 2$.
3. Формируется блок данных: $DB = lHash \parallel PS \parallel \text{0x01} \parallel M$.
4. Генерируется случайный массив $seed$ длины $hLen$.
5. Маскируется DB с помощью Mask Generation Function (MGF1):
$$dbMask = MGF(seed, k - hLen - 1)$$
$$maskedDB = DB \oplus dbMask$$
6. Маскируется seed:
$$seedMask = MGF(maskedDB, hLen)$$
$$maskedSeed = seed \oplus seedMask$$
7. Итоговое сообщение для сырого RSA:
$$EM = \text{0x00} \parallel maskedSeed \parallel maskedDB$$.

_**Mask Generation Function (MGF1)**_

MGF1 принимает на вход байтовую строку $Z$ и желаемую длину $L$. Она конкатенирует хеши от $Z \parallel C$, где $C$ — 4-байтовый счетчик (от 0 и далее), пока не наберется $L$ байт.

### 4. Задачи оптимизации Constant-time и защита памяти

Для исключения атак по побочным каналам необходимо изолировать условные переходы, зависящие от секретных данных. Использование динамических вложенных контейнеров для матриц или паддинга категорически недопустимо, так как это вызывает промахи в кэше процессора и нарушает безопасность. Данные должны размещаться исключительно в непрерывных блоках памяти с фиксированным размером.

**_Атака Блейхенбахера/Мангера на OAEP_**

При деинкапсуляции $EM$ проверяется: первый байт должен быть 0x00, хеши $lHash$ должны совпадать, разделитель 0x01 должен присутствовать. Если при невыполнении любого условия функция сразу возвращает ошибку (early exit), время работы функции выдает валидность структуры $EM$.
Constant-time защита: все проверки выполняются до конца, вводится аккумулятор ошибки (bitmask), который логическим XOR собирает все отклонения, итоговое извлечение сообщения происходит через безопасный перенос данных по маске.

**_Лестница Монтгомери_**

Алгоритм модульного возведения в степень содержит ветвление if (bit == 1) { res = (res * base) % mod; }. Это уязвимо к SPA-анализу. Лестница Монтгомери выполняет фиктивные умножения, обеспечивая строго одинаковый набор операций на каждый бит секретной экспоненты независимо от его значения.

### Требования к структуре и содержанию отчета

Отчет должен содержать:
1. Математическая часть: аналитический вывод ускорения расшифрования с помощью CRT (алгоритм Гарнера) с демонстрацией на малых числах.

3. Анализ безопасности (Constant-time): демонстрация того, что динамические многомерные контейнеры не используются, а память аллоцируется фиксированными блоками, строгое доказательство отсутствия ветвлений, зависящих от секрета, в рамках выполнения индивидуального задания.
4. Результаты тестирования: проверка корректности работы схемы при граничных условиях (длина сообщения равна 0 байт, длина равна максимальному значению $k - 2 \cdot hLen - 2$), измерение тактов процессора для доказательства Constant-time природы (сравнение времени расшифровки валидного и намеренно поврежденного шифротекста).
